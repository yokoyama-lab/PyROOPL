# 引き継ぎ: ROOPL++／PyROOPL への入出力機構の追加

作成: 2026-07-10（横山研・gen_janus プロジェクトからの依頼）

## 実装状況（2026-07-10 PyROOPL 側で対応済み）

**推奨案 A（出力宣言＋非出力クリーン検査）と exit コードの是正（補足 #1）を実装した。** gen_janus 側の検証器・参照解答・プロンプト部品はこの仕様に合わせて対応してよい。

- **構文**: main を持つクラス本体に `output id, id, ...` 宣言行を追加できる（フィールド宣言の後・メソッド宣言の前）。専用キーワード `output` を追加。宣言は複数行可。
- **意味論**: `output` 宣言があるとき、`main` 実行後に
  - 宣言された出力フィールドの最終値**のみ**を返す／表示する、
  - **非出力フィールドはすべてクリーン**であることを検査する（整数=0、オブジェクト参照=nil、配列=全要素0）。破れれば実行時エラー `ERROR:Non-clean termination: field 'k' = 3 (expected 0)`（配列は `field 'xs[1]' = 9`、生存オブジェクトは `field 'p' is a live object (expected nil)`）。
  - 出力名が実フィールドでなければ `ERROR:output field 'q' is not a field of class Program`。
- **後方互換**: `output` 宣言の無いプログラムは従来どおり全フィールドを返し、クリーン検査もしない（`example/` の139例題は無改変で通過）。**`example/` には `output` を使う例は追加していない**（OCaml 版が未対応で gen_janus 差分テストのパースを壊すため）。仕様の実行例は `tests/test_output.py` を参照。
- **exit コード**: 実行時エラー（非クリーン終了を含む）で **exit 1** を返すようにした（従来は実行時エラーでも exit 0）。stdout に出る `ERROR...` メッセージは従来どおり。副作用として `example/algo_josephus.rplpp`（既知の配列範囲外バグ）と `example/callValue_error.rplpp`（意図的エラー例）が exit 1 になる（出力内容は不変）。
- **未対応**: 案 B（明示的入出力文 `read`/`write`）は将来課題のまま。未決事項3（オブジェクト参照フィールドの nil 必須）は「生存オブジェクト参照＝非クリーン」として実装（nil = IntVal 0 のみ clean）。

## なぜ必要か（背景）

gen_janus の評価基盤では、生成された可逆プログラムの成功条件に「**クリーン終了**」を課している。Janus では、プログラムが「出力変数」を宣言し、**それ以外の補助変数がすべて 0 に戻っていること**を検査できる。これが可逆プログラムの品質（ゴミを残さない）の核心である。

ところが現在の ROOPL++／PyROOPL には**出力の宣言という概念がない**。`eval_prog` は最上位 `Program` オブジェクトの全フィールドの最終値をそのまま返し（`printer.print_result`）、「どれが出力で、どれがゴミか」の区別がない。このため：

- 検証器（gen_janus 側 `verify_rooplpp.py`）は Program フィールドしか観測できず、**局所変数のクリーン消去は PyROOPL ランタイムの可逆性表明（delocal 出口表明・delete 時ゼロ検査）が強制する**ため、検証器の `clean` フラグは局所変数に対して実質トートロジー（常に真）になっている。
- 結果として「クリーン終了を課している」という主張が、ROOPL++ では Janus ほど厳密に成立しない。**言語をまたいだ公平な比較**（本研究の目的）のために、ROOPL++ でもクリーン終了を実質的な検査項目にしたい。

そこで、**入出力機構**を追加し、「宣言された出力」と「それ以外（クリーンに消えるべき状態）」を区別できるようにしたい。

## 何を追加するか（設計案）

### 推奨案 A: 出力フィールドの宣言 ＋ 非出力状態のクリーン検査
最小で Janus のモデルに最も近い。

1. `Program` クラスのフィールドに**出力宣言**を導入する（構文は要検討。例: `output int r` / 既存フィールドに注釈 / あるいは専用の `output r, s` 宣言行）。
2. `main` 実行後、インタプリタは
   - 宣言された出力フィールド → その最終値を出力として返す（現状の `print_result` 相当）、
   - **非出力フィールド → すべて 0／nil であることを検査**し、破れていれば「非クリーン終了」エラー（可逆性表明と同種の実行時エラー）とする。
3. 出力宣言が無いプログラムは現状どおり全フィールドを出力扱い（**後方互換**。既存 example/ の139例題を壊さない）。

これにより「入力＝main で設定した初期フィールド」「出力＝宣言フィールド」「ゴミ＝それ以外（0 必須）」という Janus と同型の三分法が ROOPL++ でも成立する。

### 代替案 B: 明示的な入出力文
`read`／`write`（または `input`／`output`）文を言語に追加し、値を外部チャネルへ授受する。出力は write された値、Program フィールドは全て終了時 0／nil を要求。表現力は高いが、可逆言語での入出力文の意味論（write の逆＝unwrite で値を消費して復元できるか等）の設計が重く、可逆性との整合に注意が要る。第1段では過剰と考える。

→ **推奨は案 A**（宣言＋非出力クリーン検査）。案 B は将来課題。

## gen_janus 検証器が必要とするインタフェース

`verify_rooplpp.py` が機械判定できるよう、次のいずれかを提供してほしい：

- **終了コード**: 非出力フィールドが 0／nil でなければ**実行時エラーとして非ゼロ相当**（現状 PyROOPL は実行時エラーでも exit 0。出力中の `ERROR` 文字列で判定している。非クリーン終了も同様に明確なエラーメッセージを stdout/stderr に出すこと。メッセージ例: `Non-clean termination: field 'k' = 3 (expected 0)`）。
- **出力の分離表示**: `print_result` を「宣言出力のみ表示」に変更できる（または別モードを用意）と、検証器が期待値照合を出力フィールドだけに限定でき、堅牢になる。

## 影響と移行

- **参照解答15本**（gen_janus `260708_roopl/harness/solutions/rooplpp/`）: 出力フィールドの宣言を追記する（例: p_gcd なら `output` は無く a,b が不変・r が結果、p_fib なら r が出力で n は 0 消費）。現状すでに「出力以外は 0／nil に戻す」よう書かれているので、宣言を足すだけで実質クリーン検査が有効になる見込み。
- **検証器 `verify_rooplpp.py`**: 非クリーン終了エラーの分類（IRREVERSIBLE と別に CLEAN_FAIL 等）を追加。
- **プロンプト部品**: 出力宣言の書き方を BNF・静的制約に追記（Janus 版の「出力変数以外は 0」に対応）。
- **後方互換**: 出力宣言の無いプログラムは従来動作（139例題は無改変で通ること）。

## 未決事項（実装者への申し送り）

1. 出力宣言の構文（フィールド注釈 / 専用宣言行 / 型修飾子）。ROOPL++ の既存文法との親和性で決める。
2. 配列（LocsVec）の「クリーン」の定義（全要素 0 か、nil か）。gen_janus の配列消費タスク（rle 等）は全要素 0 復帰を要求している。
3. オブジェクトフィールド（参照）の非出力クリーンは nil 必須とするか。
4. 案 A で十分か、将来 case study（CJanus 等）で案 B が要るか。

## 補足（差分テストで見つけた既存の申し送り）

- PyROOPL は**実行時エラーでも exit 0**を返す（構文エラーのみ exit 1）。gen_janus 差分テスト（`260708_roopl/m0_difftest/`）で OCaml 版と 139/139 一致を確認済みだが、この exit コード方針は検証器泣かせなので、本機構の追加に合わせて**実行時エラー・非クリーン終了で exit 1** に揃えることを推奨（`m0_difftest/report.md` 提案 #1）。
- 例題 `example/algo_josephus.rplpp` に配列範囲外の既存バグ1件（両処理系で同一挙動、コーパス側の問題）。
